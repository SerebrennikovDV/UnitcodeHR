# UnitcodeHR — Рекрутинговая информационная система ООО «Юниткод»

Веб-приложение для управления процессом подбора персонала с модулями HR-аналитики и автоматизированного скрининга резюме.

**Тема ВКР:** Проектирование рекрутинговой информационной системы на основе HR-аналитики
**Автор:** Серебренников Д. В., 38.03.05 «Бизнес-информатика», профиль «Цифровая экономика»
**Руководитель практики:** Королькова И. А. (МУ им. С. Ю. Витте)
**Руководитель от организации:** Лобов М. Н. (ООО «Юниткод»)

## Назначение

Система автоматизирует полный цикл подбора персонала: формирование заявок на вакансии, ведение базы кандидатов, движение по этапам воронки, проведение интервью, формирование офферов и регистрацию выхода на работу. Дополнительно реализован модуль автоматического скрининга резюме на основе классических алгоритмов обработки текста.

## Ключевые возможности

- **Управление вакансиями** — заявки от нанимающих менеджеров, согласование вилки ЗП у директора, публикация на публичной странице
- **База кандидатов** — карточки с прикреплёнными резюме, поиск, дедупликация по контактам, история взаимодействия
- **Воронка подбора** — настраиваемые этапы, перевод между этапами с фиксацией истории, планирование интервью
- **Автоматический скрининг резюме** — извлечение текста из PDF / DOCX, лемматизация русского языка через pymorphy3, расчёт интегрального показателя соответствия (score) методом TF-IDF + правила, авто-отклонение при score < 50 %
- **Коннекторы к внешним источникам** — единый интерфейс для hh.ru, SuperJob, Avito с mock-реализациями (для запуска без API-ключей)
- **HR-аналитика** — time-to-hire, source-of-hire, конверсии воронки, cost-per-hire, дашборд руководителя
- **Экспорт** — офферы в .docx, аналитические отчёты в .xlsx
- **Роли** — Администратор, HR-менеджер, Нанимающий менеджер

## Установка и запуск

### Требования

- Python 3.12+
- PostgreSQL 16 (для производственного режима)

### Локальный запуск

```bash
git clone https://github.com/SerebrennikovDV/UnitcodeHR.git
cd UnitcodeHR

# Создать виртуальное окружение
python -m venv venv
# В Windows:
venv\Scripts\activate
# В Linux/macOS:
source venv/bin/activate

# Установить зависимости
pip install -r requirements.txt

# Подготовить настройки
cp .env.example .env
# Отредактировать .env и задать DJANGO_SECRET_KEY (любая случайная строка) и DATABASE_URL

# Применить миграции и загрузить тестовые данные
python main.py migrate
python main.py loaddata fixtures/initial_catalog.json fixtures/demo_users.json

# Создать суперпользователя
python main.py createsuperuser

# Запустить сервер
python main.py runserver
```

После запуска приложение доступно по адресу `http://127.0.0.1:8000/`.
Административная панель — `http://127.0.0.1:8000/admin/`.

### Тестовые учётные записи

После загрузки фикстур `demo_users.json` доступны:

| Роль | Логин | Пароль |
|---|---|---|

| HR-менеджер | hr@unitcode.local | HrUser#2026 |

```
├── unitcode_hr/            — конфигурация Django
├── apps/                   — прикладные модули
│   ├── accounts/           —   пользователи и роли
│   ├── catalog/            —   справочники
│   ├── vacancies/          —   заявки и вакансии
│   ├── candidates/         —   кандидаты и резюме
│   ├── pipeline/           —   воронка подбора
│   ├── offers/             —   офферы и наймы
│   ├── screening/          —   автоматический скрининг резюме
│   ├── analytics/          —   HR-аналитика и отчёты
│   ├── feedback/           —   форма обратной связи
│   ├── audit/              —   журнал действий
│   └── core/               —   общие утилиты
├── connectors/             — коннекторы к внешним источникам вакансий
│   ├── base.py             —   BaseVacancyConnector
│   ├── hh.py               —   hh.ru (mock)
│   ├── superjob.py         —   SuperJob (mock)
│   ├── avito.py            —   Avito (mock)
│   └── fixtures/           —   тестовые JSON-ответы
├── templates/              — HTML-шаблоны
├── static/                 — CSS, JS, изображения
├── media/                  — загружаемые файлы (резюме, экспорты)
├── fixtures/               — начальные данные (справочники, пользователи)
└── docs/                   — документация (схема БД, ER-диаграммы, скриншоты)
```
